================================================================================
3. PRINCIPIO CENTRAL DE LA APP
================================================================================

> El presupuesto no es el punto de partida. Es consecuencia del estado financiero.

Flujo maestro:
  Perfil financiero
    → Estado financiero anual (auto-generado)
        → 12 meses proyectados
            → Registros reales mes a mes
                → Análisis de desviación
                    → Alertas y recomendaciones

El usuario configura su realidad (ingresos, fijos, variables, deudas) y la app
genera todo lo demás automáticamente. Nada existe aislado — cada cambio en el
perfil recalcula el estado anual y los 12 meses automáticamente.

7. REGLAS CRÍTICAS DE BACKEND (MySQL 5.6 + mysql2)
================================================================================

1. LIMIT no parametrizado: usar `LIMIT ${parseInt(n)}` NUNCA `LIMIT ?`
2. undefined → null: pasar `campo ?? null` en arrays de bind params
   (mysql2 rechaza undefined con "Bind parameters must not contain undefined")
3. LONGTEXT para JSON: CREATE TABLE usa LONGTEXT, no JSON type
4. connectionLimit = 3: NUNCA hacer más de 3 queries en paralelo
5. Recálculo fire-and-forget: `_recalcularEstimadosAnio(uid, year).catch(() => {})`
6. Logs activos: agregar `_logInfo(ruta, mensaje, uid)` en endpoints de escritura
7. Auto-limpieza logs: setInterval cada 60 min borra registros >60 min
8. COUNT(*) retorna BigInt: usar `Number(countRow.total)` para JSON serialization

11. TRAMPAS CONOCIDAS (NO REPETIR)
================================================================================

  - LIMIT ? falla en MySQL 5.6: usar `LIMIT ${parseInt(n)}`
  - undefined en bind params: siempre `campo ?? null`
  - COUNT(*) retorna BigInt: `Number(row.total)` para JSON
  - calendar_eventos debe existir antes de PUT en gastos fijos
  - firebase_uid es el email, no un UUID de Firebase
  - APK siempre después de backend deploy (comparten conexiones MySQL)
  - gastos_variables_base.aplica_meses es LONGTEXT (JSON string), no array
  - Meses en meses_financieros deben existir antes de POST /registros
  - actualizarGastoFijo ahora lanza Exception (no retorna bool)
  - crearGastoFijo ahora lanza Exception (no retorna null)
  - MySQL retorna Decimal como string "0.00" → es TRUTHY en JS
    Nunca: Number(row.campo || row.otro)
    Siempre: Number(row.campo) || Number(row.otro)
  - meses_financieros NO tiene columna updated_at
  - flutter build web sin flutter clean puede servir código viejo (caché incremental)
    SIEMPRE: flutter clean && flutter build web --release
  - Verificar strings del sprint en build/web/main.dart.js antes de subir
  - El service worker de Vercel tiene skip-waiting en web/index.html (auto-actualiza)
  - Tabla expense_definitions existe desde v5.0 — definition_id en registros_gasto

2. INFRAESTRUCTURA
================================================================================

Backend:
  - Plataforma: Render (free tier — duerme tras 15min, cold start ~50 seg)
  - URL: https://presupuestos-backend-h3l6.onrender.com

presupuestos

gastos  (plantillas de gasto, no transacciones reales)

movimientos (transacciones reales dentro de un período)
  id, presupuesto_id, periodo_id, gasto_id,

  monto_pagado_real, pagado_por_uid, fecha_pagado,
  firebase_uid, created_at

calendario_eventos
  id, firebase_uid, gasto_id, titulo,
  tipo ENUM('pago','cobro'),
  fecha_evento, monto_esperado,
  estado ENUM('pendiente','pagado','vencido'),
  notificacion_activa, dias_anticipacion, notificacion_enviada,
  google_event_id, periodo_id,
  cobro_id INT NULL,   ← AGREGADO en esta sesión (vincula evento → cobros_clientes)
  created_at, updated_at

--- MÓDULO COBROS ---

presupuestos_produccion
  id, firebase_uid, nombre, descripcion, created_at

items_produccion
  id, presupuesto_produccion_id, firebase_uid,
  nombre, cantidad DECIMAL(10,3), precio_unitario, created_at

ventas
  id, firebase_uid, nombre,
  presupuesto_produccion_id INT NULL (legacy, se mantiene para compat),
  inversion DECIMAL(10,2) NULL  ← Bug 2: inversión manual del usuario
  estado ENUM('activa','cerrada'), created_at

cobros_clientes
  id, venta_id, firebase_uid, nombre_cliente,
  monto DECIMAL(10,2) NOT NULL,
  monto_manual TINYINT(1) DEFAULT 1,  ← PENDIENTE migración en prod
    (1 = monto ingresado manual / 0 = calculado desde pedido_items)
  condicion_pago ENUM('contra_entrega','plazo'),
    ← PENDIENTE migrar a ENUM('contra_entrega','plazo','fecha_especifica')
  dias_plazo INT NULL,
  fecha_cobro DATE NULL,
  fecha_pago_especifica DATE NULL,    ← PENDIENTE migración en prod
  estado ENUM('pendiente','cobrado'),
  monto_cobrado, fecha_cobrado, calendario_evento_id,
  created_at

--- MÓDULO MULTI-PRESUPUESTO (NUEVO - Fase 2) ---

venta_presupuestos
  id, venta_id, presupuesto_produccion_id, created_at
  UK: (venta_id, presupuesto_produccion_id)
  FK: venta_id → ventas(id) CASCADE
  FK: presupuesto_produccion_id → presupuestos_produccion(id) CASCADE

--- MÓDULO CATÁLOGO DE PRODUCTOS (NUEVO - Fase 1) ---

productos
  id, firebase_uid, nombre, descripcion,
  activo TINYINT(1) DEFAULT 1, created_at

variantes_producto
  id, producto_id, nombre,
  tamano VARCHAR(100) NULL   ← Mejora 1: tamaño libre (pequeño, mediano, grande)
  precio DECIMAL(10,2),
  unidad VARCHAR(50) DEFAULT 'unidad',
  activo TINYINT(1) DEFAULT 1, created_at
  FK: producto_id → productos(id) CASCADE

pedido_items
  id, cobro_cliente_id, variante_id INT NULL,
  descripcion VARCHAR(255),
  cantidad DECIMAL(10,3), precio_unitario DECIMAL(10,2),
  subtotal DECIMAL(10,2),   ← calculado en app: cantidad * precio_unitario
  created_at
  FK: cobro_cliente_id → cobros_clientes(id) CASCADE
  FK: variante_id → variantes_producto(id) SET NULL

11. CONVENCIONES DEL PROYECTO
================================================================================

FLUTTER:
  - Estado de carga: siempre con Container(color: AppTheme.background) como wrapper
  - Errores de red: ScaffoldMessenger.of(context).showSnackBar(SnackBar(content: Text('Error: $e')))
  - Campos numéricos de API: siempre double.tryParse(v?.toString() ?? '0') ?? 0.0
  - Campos int de API: siempre int.tryParse(v?.toString() ?? '0') ?? 0
  - Fechas: comparar como String 'YYYY-MM-DD', NUNCA con isSameDay() (bug de timezone)
  - Navegación: pushAndRemoveUntil para logout, push normal para el resto

BACKEND:
  - Todos los endpoints validan firebase_uid
  - DELETE siempre verifica propiedad con WHERE firebase_uid = ?
  - try/catch en todos los endpoints con res.status(500)
  - Fechas: comparar como strings ISO, no como Date objects (timezone issues)
  - Pool de conexiones: createPool (NO createConnection)
  - Cron job a medianoche Panama (UTC-5) para marcar eventos vencidos

GIT:
  - Rama: main
  - Un commit por cambio/feature
  - Formato: [tipo]: descripción en español
    tipos: fix, feat, backend, schema, docs, audit
